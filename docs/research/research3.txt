You can make this happen soon by treating it as two demos sharing one tiny model format:

moe-microscope: “train a docent” — an educational page where visitors can watch a tiny MoE learn the campus domain, inspect routing/expert specialization, retrain it, and export weights.
sw-campus: “ask the docent” — a polished, lightweight inference-only assistant integrated into each lobby/easel, using a pre-trained model shipped with the site.

That separation keeps sw-campus pleasant while turning moe-microscope into the microscope for exactly the same model.

Your existing MicroMoE is already at the right scale: the current top-1 model is only 7,096 parameters / ~55 KiB f64, and a full expert is just 1,072 parameters. The repo is explicitly designed so every tensor, expert, routing decision, and byte can be inspected, and it already hands recordings to a generic Rust/Yew host.

8. The important separation: weights vs knowledge

Because sw-campus changes frequently, do not bake all descriptive text into model weights.

Use:

MODEL
"What does the user want?"

CATALOG
"What currently exists?"

The model knows things like:

punched card ↔ historical computing ↔ likely IBM 1130

The catalog knows:

IBM 1442 currently exists
URL = /campus/computer-history/ibm-1130/1442
summary = ...
status = open

Therefore adding:

IBM 2310 Disk Drive

may require only an updated catalog immediately.

Retraining improves recognition later.

This allows graceful stale-model operation.

And later measure catastrophic forgetting:

That turns the humble campus chatbot into a very legitimate tiny continual-learning experiment.

So I would explicitly define the milestone as

Campus Docent v0: Train a browser-resident tiny MoE to navigate among three existing, semantically distinct live exhibits — IBM 1130, APL, and RCA 1802 — with explainable routing and deterministic catalog-backed responses.

Then:

Campus Docent v1: Add the new 1442/radio exhibit after v0 is frozen and use it to demonstrate catalog/model version mismatch, incremental training, full retraining, expert adaptation, and catastrophic-forgetting measurements.

That is actually a better experimental design than if the 1442 were already available today. It gives you a naturally occurring before/after event rather than having to manufacture one.
