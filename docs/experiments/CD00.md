# CD00: campus snapshot A and the docent corpus

## Question

What does the campus docent see, and is its training set honest,
inspectable, and reproducible from the campus catalog?

## Change from the previous experiment

A second training area. The domain is no longer synthetic: it is a
snapshot of the live Software Wrighter campus catalog, reduced to the three
exhibits that exist today and their ancestors, with a reviewable docent
block per place (aliases, concepts, authored queries, canned stories).

## Configuration

| Quantity | Value |
|---|---:|
| Places (campus, 3 buildings, 4 wings, 4 exhibits) | 12 |
| Stories (2 or 3 per place; arrival, feature, detail, anecdote) | 28 |
| Status sentences with a maturity level (finished, working, early, planned) | 12 |
| Catalog bytes | 20,274 |
| Corpus rows | 965 |
| Training / validation rows (seed 0, fraction 0.75) | 724 / 241 |
| Corpus bytes | 79,947 |
| Intent labels | navigate, explain, recommend, story, status, unsupported |
| Destination labels | the 12 places plus none |
| Held-out paraphrases (never trained on) | 54 |

Destinations that exist today: the IBM 1130 system emulator, the RCA COSMAC
1802 (assembly emulator and I/O demo), and APL on COR24. The Computational
Sciences Institute, its machine learning wing, and the MoE Microscope
exhibit are included with maturity early, so the docent can direct visitors
to this work and say honestly that the live demo is not published yet. The
IBM 1442 and its radio demo are excluded on purpose; they are the
new-knowledge event of the v1 saga.

## Results

Rows per intent: navigate 247, explain 187, recommend 177 (11 of them
authored ambiguous rows carrying an expected top-2 set), story 125 (7
generic rows such as "tell me that again"), status 189 (6 generic rows such
as "what works here"), unsupported 40. Corpus generation takes about 0.15 s
in the interpreter. The catalog hash of snapshot A is 1356782549 (a base-31
rolling checksum; the language has no hash builtin). A separate fixture of
54 paraphrases (phrasings with no alias verbatim, plus off-topic questions)
is never trained on; it is where a model must prove value over the
deterministic matcher (MB01).

## What we learned

- The catalog can be the corpus. A deterministic generator over a few
  hundred reviewable rows gives every alias, concept, and authored question
  a label without any randomness, and the whole training set fits on a
  screen.
- Shared concepts must not generate rows (one text, two labels); ambiguity
  is authored explicitly instead, which is what the CD04 panel needs.
- Work-in-progress is catalog text too: each place carries a maturity level
  and one canned status sentence; a status intent ("is the 1130 emulator
  finished?") selects it, so the docent can say what is finished, working,
  early, or planned without any of it living in weights.
- The story policy is a small deterministic function over the catalog and a
  told record: arrival once, untold first (destination and concept, then
  the current place, then ancestors), repeat only on request. The model only
  has to say that a story is wanted.
- Language constraints shaped the data structure: no lists of records, no
  string-list append, no lowercase or hash builtin. Parallel string lists
  with pipe-joined sub-lists, join-then-split accumulation, lowercase by
  construction, and a rolling checksum cover all four.

## What we did not prove

Nothing about a model yet: CD01 trains the first classifier on these rows.
Whether 563 templated rows generalize to how visitors actually phrase
questions is exactly what the held-out split and the authored rows will
measure.
