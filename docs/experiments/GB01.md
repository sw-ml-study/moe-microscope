# GB01: generation benchmark

## Question

How fast is it: time to first token, throughput, and tail latency for the
four trained shapes?

## Change from the previous experiment

Freshly built (untrained) DN01, MX01, MX02, and LD01 models under padded
greedy generation with sparse dispatch; prompt encoding precomputed
outside the timed region.

## Configuration

Measure mode records on this machine into
`fixtures/benchmark/generation-v0.json`; render mode writes the document
from the fixture, so the gate does not depend on timing noise.

## Results

| Model | Warm TTFT | Generation tok/s | p95 token | Expert evals per token |
|---|---:|---:|---:|---:|
| DN01 dense | 0.18 ms | 5,960 | 0.19 ms | 1 FFN |
| MX01 top-1 | 0.32 ms | 3,170 | 0.34 ms | 1 |
| MX02 top-2 | 0.49 ms | 2,020 | 0.59 ms | 2 |
| LD01 shared plus 16 deltas | 0.30 ms | 3,110 | 0.35 ms | 1 plus shared |

Source: [generation benchmark](../reference/generation-benchmark.md).

## What we learned

Cost per generated token follows expert evaluations plus dispatch
overhead; the mixtures are about half the dense throughput in this
interpreter ([finding 5](../results/current-findings.md)).

## What we did not prove

Anything portable: interpreter timings on one machine. The CUDA saga
re-measures on different hardware.
